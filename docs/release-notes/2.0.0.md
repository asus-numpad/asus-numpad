这一版换了名字，也换了适用范围。

项目从 `asus-numpad` 改名 `numdeck`，组织改成 `numdeck-dev`。原名把话说小了：运行期
判断本来就只看 DMI 字段与触摸板模块，跟机器是谁家的没关系，`docs/machines.md` 里那张
机型表用的也是这两个值。别的品牌只要用同款 I2C-HID 数字键盘触摸板，装上就能跑，名字
却写着「只给华硕」。新名字只说这东西是干什么的，不限定谁的机器。站点跟着搬到
`numdeck-dev.github.io`，仓库地址、raw 源、Nix flake、AUR 与 Gentoo 里的 URL 全部同步；
旧地址仍有 GitHub 的重定向，老脚本不会立刻断。

另一半是架构。骁龙 X 与 RTX Spark 这类 ARM64 笔记本已经能跑完整桌面，之前却只有
x86_64 的包，装完还得自己编。现在 deb、rpm、apk、tarball 各出两份：`--arch arm64`
指定架构，交叉编译交给 zig，构建机是不是 ARM 都无所谓。仓库索引按架构分了目录，
安装命令里用 `$(uname -m)` 选一份，两种机器贴同一行。发版流水线按「架构 × 包格式」
展开，ARM 那份在原生 arm runner 上构建，install-check 也在 ARM 容器里真装一遍再发。
pacman 仍是 x86_64：Arch Linux ARM 是独立生态，自己的仓库与签名，官方仓库不收
aarch64 包；PKGBUILD 里已声明 `aarch64`，ArchLinuxARM 用户 `makepkg` 即可。

除此之外还有一批结构与无人值守的改动（大文件拆目录、挂起恢复、事件流断裂），
细节见 [CHANGELOG.md](https://github.com/numdeck-dev/numdeck/blob/main/CHANGELOG.md)。
